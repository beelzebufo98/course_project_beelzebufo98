# P12 - IaC & Container Security Summary

## Обзор
В рамках задания P12 в CI были настроены автоматические проверки:
- Dockerfile - с помощью Hadolint;
- IaC (docker-compose) - с помощью Checkov;
- контейнерного образа - с помощью Trivy.

Все отчёты сохранены в каталоге `EVIDENCE/P12/` и приложены к PR.

## Hadolint (Dockerfile)

**Отчёт:** `EVIDENCE/P12/hadolint_report.json`

- Hadolint успешно запущен в CI.
- Критичных ошибок не выявлено.
- Используется конфигурация `security/hadolint.yaml`:
  - отключены правила `DL3008`, `DL3013`, неактуальные для проекта;
  - порог отказа установлен на уровне `warning`.

**Вывод:** Dockerfile соответствует базовым практикам контейнерной безопасности.

## Checkov (IaC)

**Отчёт:** `EVIDENCE/P12/checkov_report.json`

- Checkov успешно запускается в CI.
- Сканирование выполнено по `docker-compose.yaml`.
- В текущей конфигурации:
  - ресурсов для анализа не обнаружено (`resource_count = 0`);
  - ошибок и нарушений не выявлено.

Это ожидаемо для минимального compose-файла без расширенных security-настроек.

## Trivy (Container Image)

**Отчёт:** `EVIDENCE/P12/trivy_report.json`

- Образ собран локально в CI и просканирован Trivy.
- Обнаружены уязвимости уровня **HIGH**.
- Все найденные уязвимости имеют статус `fixed`:
  - обновление пакетов в базовом образе устраняет проблему.

**Вывод:** уязвимости зафиксированы, риск признан контролируемым.
В дальнейшем возможно:
- обновление base-образа;
- включение политики fail-on-high после стабилизации зависимостей.

## Применённые меры харднинга

- Используется фиксированная версия base-образа;
- Конфигурация и секреты не хардкодятся в Dockerfile;
- В CI внедрены:
  - linting Dockerfile,
  - IaC security scan,
  - image vulnerability scan.
