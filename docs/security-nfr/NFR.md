# NFR.md — Таблица требований безопасности (шаблон)

| ID | Название | Описание | Метрика / Порог | Проверка | Компонент | Приоритет |
|----|-----------|-----------|-----------------|-----------|------------|------------|
| **NFR-01** | Контроль доступа (AuthZ) | Только владелец может просматривать, редактировать или удалять свои желания. Доступ к чужим данным запрещён. Любые попытки несанкционированного обращения должны фиксироваться в логах. | 100 % запросов, где `user_id ≠ owner_id`, возвращают `403 Forbidden`. Нулевая доля утечек данных. | e2e-тесты на изолированных пользователях + проверка логов | `api/auth`, `middleware` | **High** |
| **NFR-02** | Аутентификация (AuthN) | Сервис использует JWT-токены с чётким сроком действия. Все защищённые эндпоинты требуют токен. | TTL access-токена ≤ 60 минут, refresh-токена ≤ 30 дней; 100 % защищённых маршрутов проверяют `Authorization`-заголовок. | unit-тесты middleware + ручная проверка конфигурации JWT | `auth` | **High** |
| **NFR-03** | Валидация пользовательского ввода | Вводимые данные проверяются по типам и диапазонам. Ошибочные данные не должны менять состояние. | 100 % некорректных запросов (`price_estimate < 0`) → HTTP 400; записи в БД не создаются/не обновляются. | unit + integration-тесты | `api/validation` | **High** |
| **NFR-04** | Формат ошибок и прозрачность API | Все ошибки возвращаются в формате **RFC 7807** (`application/problem+json`), с кодом и описанием, без утечки PII. | 100 % эндпоинтов возвращают корректный `problem+json`; 0 % персональных данных в теле ответа. | contract tests + static-анализ ответа | `api/core` | **Medium** |
| **NFR-05** | Производительность (Response Time) | Среднее время отклика сервиса должно оставаться в допустимых пределах при типовой нагрузке. | p95 для `GET /wishes` ≤ 200 мс при 30 RPS| performance-тесты| `api`, `db` | **High** |
| **NFR-06** | Экспорт данных | Экспорт должен быть безопасным, быстрым и не приводить к утечкам. Пользователь может экспортировать только свои записи. | Размер ответа ≤ 5 МБ, p95 время ≤ 500 мс при 10 RPS; 100 % случаев — данные принадлежат владельцу. | e2e + performance-тесты | `api/export` | **Medium** |
| **NFR-07** | Безопасность зависимостей (SCA) | Проект не должен содержать известных уязвимостей уровня High/Critical. | Отчёт `pip-audit` в CI показывает 0 уязвимостей High+; исправления — ≤ 2 дней с момента обнаружения. | автоматический SCA в CI/CD | `build`, `pipeline` | **High** |
| **NFR-08** | Целостность и устойчивость данных БД | Система обязана сохранять консистентность данных и корректно обрабатывать ошибки при операциях БД. | 100 % нарушений FK → ошибка; время холодного старта миграций ≤ 2 с; ни одного сбоя при аварийном завершении тестового сценария. | integration tests + pytest fixtures | `db` | **Medium** |
