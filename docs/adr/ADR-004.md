# ADR-004: Rate limiting и контроль производительности API

Дата: 2025-10-19
Статус: Accepted

## Context
В рамках требований **NFR-05** и анализа рисков (**R10: Замедление API при нагрузке (DoS)**) выявлено, что при повышенной нагрузке без ограничений скорости запросов возможна деградация производительности:
- рост p95 отклика до > 300 мс;
- перегрузка БД;
- нестабильность времени отклика при 30+ RPS.
Для обеспечения стабильной работы и выполнения NFR-05 необходимо внедрить ограничение частоты запросов (rate limiting) на уровне API.

## Decision
Реализовать rate limiting через middleware уровня приложения с использованием библиотеки [`slowapi`](https://pypi.org/project/slowapi/).
Решение интегрируется с FastAPI и совместимо с существующим форматом ошибок RFC 7807.

### Основные параметры
- **Базовый лимит:** 30 запросов/секунду на один IP (в соответствии с нагрузочным сценарием).
- **Ответ при превышении:** `429 Too Many Requests` в формате `application/problem+json`.

## Alternatives

| Вариант                               | Плюсы                                                         | Минусы                                      |
| ------------------------------------- | ------------------------------------------------------------- | ------------------------------------------- |
| Ограничение через Nginx / API Gateway | Высокая производительность, централизованный контроль         | Требует внешней инфраструктуры              |
| Ограничение на уровне БД              | Простота реализации                                           | Не предотвращает перегрузку API             |
| **slowapi middleware (выбран)**       | Простая интеграция, гибкая настройка, совместимость с FastAPI | Работает в рамках одного инстанса без Redis |


## Consequences

**Преимущества**

* Стабильное p95 ≤ 200 мс при 30 RPS (выполнение NFR-05).
* Предотвращение перегрузки API и базы данных.
* Повышение устойчивости без изменений инфраструктуры.

## Security impact

* Устраняет риск **R10 (замедление API при DoS)** из `RISKS.md`.
* Соответствует STRIDE-категории **Denial of Service**.
* Повышает надёжность API при стресс-тестах (30 RPS и выше).

## Rollout plan

1. Добавить зависимость `slowapi` в `requirements-dev.txt`.
2. Написать тесты
