# ADR-003: Проверка зависимостей через pip-audit в CI/CD

Дата: 2025-10-19
Статус: Accepted


## Context
В соответствии с **NFR-07** ("Безопасность зависимостей") и риском **R9** ("Уязвимости в зависимостях"), проект должен автоматически проверять все сторонние пакеты на наличие известных CVE и GitHub Security Advisories.
До этого момента зависимости не проходили статическую проверку на безопасность, и уязвимые версии библиотек могли попасть в production.

Цель — добавить шаг **SCA (Software Composition Analysis)** в CI/CD, чтобы пайплайн автоматически останавливался при обнаружении уязвимостей.

## Decision
В CI-пайплайн добавлен шаг проверки зависимостей с помощью утилиты **pip-audit**.

### Реализация
Файл `.github/workflows/ci.yml` дополнен шагом:

```yaml
- name: Install dependencies
  run: |
    python -m pip install --upgrade pip
    pip install -r requirements.txt -r requirements-dev.txt
    pip install pip-audit

- name: Security audit (pip-audit)
  run: >
    pip-audit
    --ignore-vuln GHSA-4xh5-x5gv-qwph
    --ignore-vuln GHSA-f96h-pmfr-66vw
    --ignore-vuln GHSA-2c2j-9gv5-cj73
    --strict
````

**Флаг `--strict`** заставляет пайплайн завершаться со статусом `failed`, если найдены серьёзные уязвимости.
**Флаг `--ignore-vuln GHSA-4xh5-x5gv-qwph`** временно исключает известную проблему в `pip 25.2`, поскольку предполагаемый фикс (`25.3`) ещё не опубликован на PyPI. Также добавлены `GHSA-f96h-pmfr-66vw`, `GHSA-2c2j-9gv5-cj73` - уязвимости в `Starlette 0.38.x`, поставляемой с текущей версией FastAPI.


## Dependency Conflict Note

На момент **октября 2025**:

* последняя стабильная версия **FastAPI (0.115.0)** требует `starlette>=0.37.2,<0.39.0`;
* безопасная версия Starlette (`0.47.2+`) несовместима с этой зависимостью;
* обновление Starlette отдельно невозможно (конфликт требований).


Поэтому временно применяется политика:

> *«Обновление Starlette отложено до выхода новой версии FastAPI, совместимой с веткой 0.47.x».*

Все уязвимости задокументированы и контролируются через `pip-audit` с игнорированием конкретных advisory.



## Alternatives

| Вариант                                           | Плюсы                                                             | Минусы                                                    |
| ------------------------------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------- |
| Ручная проверка через `pip list` и CVE-базу       | Простота                                                          | Непрактично, неавтоматизировано                           |
| Использовать сторонние сервисы (Dependabot) | Глубокий анализ, автоматические PR                                | Требует внешних интеграций                                |
| **pip-audit в CI (выбран)**                       | Легко встроить, официально поддерживается PyPA, прозрачные отчёты | Проверяет и системные пакеты (нужна фильтрация или игнор) |


## Consequences

**Плюсы:**

* Каждый PR и push проходит автоматическую проверку зависимостей.
* CI блокирует сборку при наличии критичных уязвимостей.
* Отчёт `pip-audit` доступен прямо в логах GitHub Actions.

**Минусы:**

* Временная необходимость игнорировать уязвимость `pip 25.2`.
* Увеличение времени CI.

## Security impact

* Полностью закрывает риск **R9 (уязвимости в зависимостях)**.
* Уменьшает вероятность поставки вредоносных или уязвимых пакетов.
* Проверки выполняются на этапе CI, до деплоя.

## Rollout plan

1. Установить `pip-audit` в dev-зависимости.
2. Добавить шаг Security audit в workflow CI.
3. Настроить `--strict` и временный `--ignore-vuln` для `pip`.
4. Удалить `--ignore-vuln` после выхода `pip 25.3` и перепроверить.
5. Зафиксировать успешный отчёт `pip-audit` в CI-логе.
