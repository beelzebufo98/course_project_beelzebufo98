# ADR-002: Управление секретами через GitHub Secrets

Дата: 2025-10-19
Статус: Accepted

## Context
Ранее приложение использовало `.env`-файлы для хранения конфигурации (`DATABASE_URL`, `TEST_DATABASE_URL`).
Такой подход небезопасен:
- `.env` может случайно попасть в репозиторий;
- секреты нельзя использовать безопасно в GitHub Actions (CI);
- отсутствует аудит и контроль доступа к переменным.

Необходимо решение, обеспечивающее:
- безопасное хранение конфиденциальных данных;
- интеграцию с CI/CD пайплайном;
- отсутствие секретов в коде и истории git.

## Decision
Выбрано использование GitHub Secrets как централизованного и безопасного способа хранения чувствительных данных.

### Реализация
- В настройках репозитория (`Settings → Secrets and variables → Actions`) добавлены переменные:
  - `DATABASE_URL` — строка подключения к основной БД;
  - `TEST_DATABASE_URL` — строка подключения к тестовой БД.
- CI-пайплайн получает эти значения через `${{ secrets.* }}` и передаёт их в окружение во время сборки и тестов.

```yaml
env:
  DATABASE_URL: ${{ secrets.DATABASE_URL }}
  TEST_DATABASE_URL: ${{ secrets.TEST_DATABASE_URL }}

steps:
  - uses: actions/checkout@v4
  - name: Install dependencies
    run: pip install -r requirements.txt
  - name: Run tests
    run: pytest -v
````

## Alternatives

| Вариант                     | Плюсы                                               | Минусы                                            |
| --------------------------- | --------------------------------------------------- | ------------------------------------------------- |
| `.env`-файлы                | Простота                                            | Высокий риск утечки; не подходит для CI           |
| Vault / Secrets Manager     | Максимальная безопасность                  | Сложность в настройке взаимодействия, стоимость поддержки         |
| **GitHub Secrets (выбран)** | Централизованно и безопасно, интегрировано с Actions | Без ротации секретов - требуется ручное обновление секретов |


## Consequences

**Плюсы:**

* Конфиденциальные данные не хранятся в коде.
* GitHub контролирует доступ и шифрует секреты на уровне репозитория.
* Простая настройка без дополнительных сервисов.

**Минусы:**

* Секреты статичны, ротация выполняется вручную.

## Security impact

* Закрывает риск **R9**.
* Полностью устраняет необходимость `.env` в репозитории.
* Гарантирует, что переменные окружения доступны только в момент выполнения CI.

## Rollout plan

1. Создать секреты `DATABASE_URL` и `TEST_DATABASE_URL` в репозитории GitHub.
2. Обновить workflow (`.github/workflows/ci.yml`) для использования `${{ secrets.* }}`.
3. Убедиться, что `app/db.py` получает переменные через `os.getenv`.
4. Проверить прохождение тестов в CI.
